# VeriScout 架构设计

本文说明 `ves` 的内部结构、数据流、关键算法与扩展方式。想先跑起来请看 [README](../README.md)，
想了解需求与取舍请看 [计划书](计划书.md)。

---

## 1. 设计原则

1. **能力即边界**：能做什么由注册表决定，而不是由提示词约束。提示词只是「说明书」，不是「锁」。
2. **单一出口**：所有网络请求都经过 `http.rs` 的加固层；所有写文件都经过工具内的路径校验。没有旁路。
3. **模型与渲染解耦**：模型输出结构化数据，Rust 负责渲染与转义。模型永远不直接拼 HTML。
4. **失败要显形**：错误不是噪音，而是结论质量的一部分；每个引擎/抓取/脚本的失败都被记录并回传给模型。
5. **纯逻辑可测**：解析、打分、脱敏、渲染、沙箱判定都不依赖网络，可在 `cargo test` 里覆盖。

## 3. 运行期结构

```
┌─────────────────────────── ves 进程 ───────────────────────────┐
│ main → cli::main                                               │
│   ├─ run/repl → Agent ──► LlmClient ──► HTTPS (模型 API)       │
│   │                │                                           │
│   │                └─► tools::dispatch ──► Ctx { cfg, http }   │
│   │                        ├─ web_search ──► thread::scope     │
│   │                        │      └─ N 个引擎线程 ──► Http     │
│   │                        ├─ curl_tool ──► Http（或 curl 子进程）│
│   │                        ├─ scripts_tool ──► python3 子进程   │
│   │                        │        （env_clear + rlimit）      │
│   │                        └─ html_tools ──► visualizations/   │
│   └─ search/fetch/call/… → 直接调用同一个 dispatch              │
└────────────────────────────────────────────────────────────────┘
```

- 唯一往外的网络出口是 `Http::fetch`，它先做策略校验再发请求。
- 唯一往外的进程出口是 `scripts_tool`（Python）与可选的 curl binary 模式，两者都不经过 shell。
- 唯一可写位置是 `visualizations/`（报告与模型）与 `raw/`（原始留档，需显式 `save=true`）。

## 4. 一次研究的完整时序

```
用户: ves "某事件是否属实"
  │
  ├─ Agent::new()  载入配置 → 解析 API Key → 组装系统提示词（含已有报告列表、可用引擎）
  │
  ├─ run(query):
  │   ├─ push user message（问题 + 当前时间 + 流程要求）
  │   └─ loop（上限 agent.max_steps）:
  │       ├─ LlmClient::chat(messages, tools)  ──► 模型返回 tool_calls 或最终回答
  │       ├─ 若 400 且拒绝 tools → 切文本协议并继续
  │       ├─ 对每个 tool_call:
  │       │     ├─ 参数 JSON 解析（容错）
  │       │     ├─ dispatch(name, args)
  │       │     │    ├─ web_search → Aggregator::search
  │       │     │    │     ├─ active_engines(scope) 过滤可用引擎
  │       │     │    │     ├─ thread::scope 并行拉取
  │       │     │    │     ├─ 黑名单过滤 + URL 归一 + 去重合并
  │       │     │    │     ├─ 打分排序 → truncate(limit)
  │       │     │    │     └─ deep=true 时再抓前 N 页正文
  │       │     │    ├─ curl_tool → vet_url → Http::fetch → 转文本 → 可选落盘 raw/
  │       │     │    ├─ scripts_tool → 写临时沙箱 → python3 → 采集 stdout/stderr/exit
  │       │     │    └─ html_tools → 校验 → 归一化 → 渲染 → 写文件
  │       │     ├─ 结果 JSON 截断到 tool_output_chars
  │       │     └─ push tool message（含 call_id）
  │       ├─ compact()  超出预算则压缩早期工具输出
  │       └─ 达到 max_tool_calls 则跳出并强制收敛
  │
  └─ 若最终没有回答 → 追加一条「请立即给结论、不要再调用工具」并用空 tools 再请求一次
     输出：answer + 新建报告路径 + 步数/工具数/tokens/耗时
```

## 5. 关键类型

### 5.1 `Ctx`（工具运行上下文）

```rust
pub struct Ctx {
    pub cfg: Config,          // 生效配置
    pub http: Http,           // 已绑定黑名单与私网策略的 HTTP 客户端
    pub session: SessionState // 本次会话的溯源信息
}

pub struct SessionState {
    pub created_reports: Vec<String>, // 本会话产生的报告名
    pub tool_calls: u32,              // 工具调用计数（用于上限与溯源）
    pub engines_used: BTreeSet<String>, // 实际成功过的引擎
    pub blocked_requests: Vec<String>,  // 被拦截的请求（写入报告页脚）
    pub fetched_urls: Vec<String>,      // 实际抓取过的 URL
}
```

### 5.2 `ToolSpec`（工具契约）

```rust
pub struct ToolSpec {
    pub name: &'static str,
    pub description: &'static str,
    pub parameters: serde_json::Value,   // JSON Schema，直接喂给模型
    pub handler: fn(&mut Ctx, &Value) -> Result<Value>,
}
```

注册表 `registry()` 是唯一的能力声明处；`openai_tools()` 由它生成模型可见的工具列表。
单测 `registry_is_exactly_the_sealed_surface` 会断言这 6 个名字，并检查没有 `bash/edit/write/read` 之类泄漏进来。

### 5.3 `Report`（报告模型）

```rust
Report { name, title, query, created_at, updated_at, theme, locale, summary,
         items: Vec<Item>, sources: Vec<Source>, events: Vec<Event>,
         relations: Vec<Relation>, notes: Vec<Note>, provenance: Provenance }
```

`Report::normalize()` 是幂等的「净化 + 补全」步骤：

- 来源：补 id（`s1`…）、补 domain、按 kind 修正类型、缺可靠性时用域名先验 + 类型加成、按归一 URL 去重。
- 主张：补 id（`i1`…），把 `source_ids` 里给的「id / URL / 序号」统一解析成 id，标注断链引用，状态归一化，置信度补默认值。
- 事件/关系：补 id、归一关系类型、丢弃指向不存在节点的边。
- 时间戳、主题、生成器信息补齐。

### 5.4 `Message` / `ToolCall`（与模型交互）

字段与 OpenAI 兼容接口一致；`tool_calls` 为空时自动尝试解析文本协议（json 代码块），
因此不支持 function calling 的模型也能驱动同一套 agent。

## 6. 检索排序算法

合并去重后，每条结果按下列公式打分（数值取自源码常量）：

```
score = trust × 0.55                      // 域名先验（gov/edu/学术/通讯社高）
      + engine_weight                     // wikipedia 16, openalex/crossref/arxiv 12, bing 10,
                                          // googlenews 8, searx/tavily/serper/brave 6, 其他 4
      + 9 × (corroboration − 1)           // 多个独立引擎命中同一 URL 的加成
      + 26 × title_overlap                // 查询词在标题中的覆盖率（中文按 bigram）
      + 10 × snippet_overlap              // 查询词在摘要中的覆盖率
      + recency_bonus                     // 90 天内的新闻按新旧给 0~10 分
      + 2   (https)
      − 6   (摘要为空)
```

去重规则：URL 归一（去 fragment、去 utm 类参数）后取 `host+path`；Wikipedia 跨语言同条目视为一个来源；
标题归一（仅字母数字、忽略大小写）相同且长度 > 12 视为同一来源。命中重复时合并为一条并累加 `corroboration`。

## 7. 上下文预算

```rust
fn compact(&mut self) {
    if total_weight <= context_budget { return; }
    // 保留 system(0) 与最近 6 条；其余 tool 消息若超过 600 字符则替换为占位说明
}
```

默认 `context_budget_chars = 220_000`、`tool_output_chars = 12_000`。
这么做的原因：一次深度研究会产生十几条工具结果（每条可达上万字符），
不压缩就会撞模型上下文上限；而压缩只针对**早期**结果，最近证据保持完整。

## 8. 渲染管线

```
Report ──► render() ──► fill(template, pairs) ──► 单文件 HTML
                          │
                          ├─ 单遍扫描 {{KEY}}：插入值不再被扫描
                          │   （所以主张里写 {{TITLE}} 也不会被替换，已被单测覆盖）
                          ├─ 所有文本走 html_escape
                          └─ 图数据走 json_for_script（转义 < > & 与 U+2028/29）
```

要点：

- **单遍替换**防止「内容注入模板」。
- **转义在先**：主张/摘要/引文全部先转义，再做 markdown 子集替换（`**粗体**`、行内代码、`- `列表、`## `小标题）。
- **图数据嵌入**：`graph()` 在无事件时退化为「主张共享来源」共现图，保证可视化不空。
- **时间线排序**：能解析出日期的按时间升序，无法解析的排在末尾。

## 9. 错误处理与降级矩阵

| 场景 | 行为 |
| --- | --- |
| 某个搜索引擎失败/改版 | 该引擎记 error，其余引擎照常；结论里能看到哪个源没取到 |
| DDG 返回反爬页 | 依次尝试 html → lite → Instant Answer API，全失败则记 error |
| SearxNG 实例失败 | 按配置顺序轮换实例，JSON 失败再试 HTML |
| 模型接口拒绝 `tools` 参数 | 降级为文本协议（json 代码块），插入使用说明后继续 |
| 模型返回空内容且无工具调用 | 追问一次；仍空则在末尾强制「无工具」总结 |
| 工具抛错 | 转成 `{"error": "..."}` 作为工具结果回传，模型可自行修正（如修正脚本违规行） |
| 脚本被沙箱拒绝 | 作为工具错误返回，附「允许的模块」与「可用 helper」清单 |
| 抓取被黑名单/私网拦截 | 明确报出「被策略拒绝」的原因，不静默重试 |
| 本地 AnySearch CLI 未安装 | 该引擎从 `active_engines` 中消失，其它引擎照常，不产生错误噪音 |
| AnySearch 服务抖动（TLS 重置 / 限流） | 子进程路径按 `net.retries` 重试（每次至少等 1.5 s）；仍失败则以 `engines[].error` 如实上报 |
| 页面直接抓取失败或正文过少 | `deep=true` 时自动改用 AnySearch `extract` 渲染，`pages[].extractor` 标明数据来源；未通过域名/私网策略的 URL 绝不外送 |
| 报告名冲突 | 自动追加 `-2` `-3`，绝不覆盖 |
| 模型给的报告参数类型不合规（数字写成字符串、列表写成单值、序号当键） | 逐元素容错解析并纠正；纠正不了的**按下标**写入 `warnings`，绝不整批静默丢弃；系统提示词要求模型核对 `stats`/`warnings` 后用 `edit_html` 补齐 |

## 11. 性能与资源

- **并发检索**：`std::thread::scope` 为每个引擎起一个线程，整体耗时约等于最慢的引擎而非求和。
- **零常驻开销**：无后台线程池、无运行时、无 GC；REPL 空闲时不占 CPU。
- **体积控制**：单次 HTTP 读取有硬上限（默认 400 KB，搜索 2 MB），超出即截断并标记。
- **脚本隔离**：Python 只在实际调用 `scripts_tool` 时按需启动，进程结束后临时目录被删除。
- **快速失败**：整段解析在内存里做字符串/正则操作，不做重量级 DOM 构建。
- **网络重试**：`net.retries`（默认 3）+ 线性退避。传输层失败对所有方法重试；429/5xx 只对 GET/HEAD 重试。
  这层是为「TLS 间歇性重置」的现实网络加的，实测把 `example.com`/`en.wikipedia.org`/`reuters.com` 从经常失败变为稳定成功。
- **正文提取**：`html_to_text` 先剥离 `script/style/noscript/svg/head` 主体，再把块级标签折成换行，最后去标签、解实体、压缩空白。
  标签匹配是**边界感知**的（`<header>` 不会命中 `<head>`）；遇到未闭合结构时保留已提取内容而不是清空全文。

## 12. 扩展指南

### 12.1 新增一个搜索引擎

1. 在 `src/search/providers/{general,vertical,keyed}.rs` 里加一个函数：
   `fn foo(http: &Http, cfg: &Config, q: &str, limit: usize) -> Result<Vec<SearchResult>>`，
   用 `mk(engine, title, url, snippet)` 构造结果，用 `fetch()/post_json()` 发请求。
2. 在 `providers/mod.rs::run()` 的 `match` 里注册名字。
3. 在 `src/config.rs` 的默认 `engines` / `vertical_engines` 中加入（垂直源还要在 `Scope::allows` 里归类）。
4. 补一条解析单测（可用内联样例 HTML/JSON）。

### 12.2 新增一个工具

1. 在 `src/tools/` 新建模块并实现 `pub fn run(ctx: &mut Ctx, args: &Value) -> Result<Value>`。
2. 在 `src/tools/mod.rs::registry()` 里追加 `ToolSpec`（名称、描述、JSON Schema、handler）。
3. 更新 `registry_is_exactly_the_sealed_surface` 与 `every_tool_has_a_valid_schema` 两条断言。
4. 若引入新的网络访问，务必走 `ctx.http` 以继承协议/黑名单/私网策略。
5. 若引入新的写文件，必须做与 `html_tools::assert_inside` 同等的路径校验。

### 12.3 换模型

- 任意 OpenAI 兼容端点：`--base-url https://your-host/v1 --model your-model`。
- 本地 Ollama：`--base-url http://localhost:11434/v1 --model qwen2.5`（无需 Key）。
- 不支持 function calling：无需改动，客户端会自动降级为文本协议。
