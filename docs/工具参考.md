# VeriScout 工具参考

这是 agent 能调用的**全部**能力（6 个）。没有 shell、没有文件读写、没有通用执行器。

- 模型调用：走 `functions/tools` 协议，schema 由 `ves tools --json` 导出。
- 人工调用：`ves call <name> --args '<json>'`，行为完全一致（同一个 `dispatch`）。
- 所有网络请求都经过加固 HTTP 层：仅 http/https、黑名单、私网拦截、体积上限。

---

## 1. `web_search`

**用途**：多引擎并行检索，返回经过黑名单过滤、跨引擎去重与打分的候选来源。

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `query` | string | ✅ | — | 查询词。建议中英文各查一次以提高覆盖面 |
| `scope` | enum | — | `web` | `web` / `news` / `academic` / `code` / `qa` / `all`，决定启用哪一类引擎 |
| `limit` | integer | — | `12` | 返回条数，1–40 |
| `engines` | string[] | — | 配置值 | 显式指定引擎（如 `["bing","wikipedia"]`） |
| `deep` | boolean | — | `false` | 是否额外抓取前几页正文并返回文本摘要 |

> **引擎**：默认 `anysearch`（本地 CLI，装了才启用）、`bing`、`wikipedia`、`duckduckgo`、`searx`；
> 垂直源 `googlenews` / `crossref` / `openalex` / `arxiv` / `hackernews` / `github` / `stackexchange`。
> `deep=true` 时若某页直接抓取失败或正文过少（典型 JS 站点），会自动改用 AnySearch `extract` 渲染成 Markdown，
> `pages[].extractor` 会标明 `http` 还是 `anysearch`。
| `deep_pages` | integer | — | `3` | `deep=true` 时抓取页数，0–8 |

### 返回

| 字段 | 说明 |
| --- | --- |
| `results[]` | 每条含 `n` `title` `url` `domain` `snippet` `engines` `trust` `score` `corroboration` `published` `extra` |
| `engines[]` | 每个引擎的 `ok` / `results` / `ms` / `error` —— **失败原因在这里可见** |
| `blacklisted_filtered[]` | 被黑名单拦掉的域名及原因 |
| `notes[]` | 「可达但没解析出结果」之类的提示 |
| `pages[]` | `deep=true` 时的正文摘要（含 `excerpt`，约 6000 字符） |
| `guidance` | 固定提示：单来源最多算 supported，两个独立域名才能算 verified |

### 示例

```bash
ves call web_search --args '{"query":"source verification methods","scope":"academic","limit":5}'
```

```json
{
  "query": "source verification methods",
  "scope": "academic",
  "count": 5,
  "results": [
    {
      "n": 1,
      "title": "…",
      "url": "https://doi.org/10.xxxx/xxxxx",
      "domain": "doi.org",
      "snippet": "… · cited by 128",
      "engines": "crossref",
      "trust": 88,
      "score": 74.2,
      "corroboration": 1
    }
  ],
  "engines": [
    { "engine": "crossref", "ok": true, "results": 5, "ms": 412, "error": null },
    { "engine": "github", "ok": false, "results": 0, "ms": 10021, "error": "transport error …" }
  ]
}
```

### 注意

- `trust` 是**域名先验分**，不是事实判断；`score` 才是本次查询的排序分。
- 引擎名可用 `engines` 限定；未知引擎名会返回错误并列出合法值。

## 2. `curl_tool`

**用途**：打开一个具体 URL 并拿到可读文本（用于逐字核实、摘录引文）。

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `url` | string | ✅ | — | 绝对 http(s) URL |
| `method` | enum | — | `GET` | `GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS`（`CONNECT/TRACE` 被拒） |
| `headers` | object | — | — | 附加请求头；含换行的值会被拒绝 |
| `body` | string | — | — | 原始请求体（≤ 1 MB） |
| `json` | object | — | — | JSON 体，自动带 `Content-Type: application/json` |
| `extract_text` | boolean | — | `true` | HTML 转可读文本；JSON 会被美化 |
| `include_headers` | boolean | — | `false` | 返回响应头 |
| `save` | boolean | — | `false` | 原始体落盘到 `raw/`，返回 `saved_path` |
| `timeout_secs` | integer | — | 配置值 | 1–120 |
| `max_bytes` | integer | — | 配置值 | 读取上限 |
| `follow_redirects` | boolean | — | `true` | 跟随重定向（上限见配置） |
| `render` | boolean | — | `false` | 交给 AnySearch 提取器渲染页面并返回 Markdown（JS 站点用）；URL 会分享给该第三方服务，且仅对已通过域名/私网策略的 URL 生效 |

### 返回

```json
{
  "status": 200,
  "url": "https://example.com/final",
  "content_type": "text/html; charset=utf-8",
  "bytes": 51234,
  "truncated": false,
  "elapsed_ms": 322,
  "engine": "native",
  "text": "……正文……",
  "note": "404: the page does not exist - do not cite it"
}
```

### 错误与拒绝

| 情况 | 结果 |
| --- | --- |
| `file://` `data://` `ftp://` | `request blocked by policy: refused scheme …` |
| 域名在黑名单 | `request blocked by policy: host 'x' matches block rule 'y'` |
| 解析到私网/回环 | `request blocked: … resolves to private address …` |
| 方法不在白名单 | `method 'CONNECT' is not allowed; permitted: …` |
| 传输失败 | `transport error for <url>: …` |

### 注意

- 默认 `curl.engine="native"`：**进程内** HTTP，无子进程，无法表达「写本地文件」。
- 可选 `binary` 模式调用系统 curl，但参数由代码从校验字段拼装、无 shell、禁用危险开关。
- HTTP 404/403/429 会附带 `note` 提醒模型不要引用。

## 3. `scripts_tool`

**用途**：在**网络只读沙箱**里跑 Python，做正则抽取、JSON 整形、去重、统计、日期计算。

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `code` | string | ✅ | — | Python 3 源码（≤ 200 KB） |
| `timeout_secs` | integer | — | 配置值 | 1–120；超时杀进程 |
| `stdin` | string | — | — | 传给脚本的标准输入 |

### 沙箱内可用的 helper

| 名称 | 说明 |
| --- | --- |
| `fetch(url, method, headers, data, timeout, max_bytes)` | 受同一套主机策略约束的 HTTP 请求，返回 `{status, url, content_type, headers, text, truncated}` |
| `fetch_json(url, **kw)` | `fetch` + `json.loads` |
| `html_to_text(html)` / `strip_tags(s)` / `truncate(s, n)` | 文本处理 |
| `emit(obj)` | 打印格式化 JSON（推荐作为输出方式） |
| `now()` | 当前 UTC ISO 时间 |
| `json` `re` `math` | 预置模块（无需 import） |

### 允许导入的模块

`json re math statistics datetime time random string itertools functools collections typing dataclasses decimal fractions hashlib hmac base64 binascii textwrap unicodedata difflib html csv urllib.parse urllib.error urllib.request http.client email.utils uuid enum operator copy contextlib warnings`

### 被拒绝的写法（执行前静态拦截，带行号）

| 类别 | 示例 |
| --- | --- |
| 文件系统 | `open(...)`、`.read()`、`.write()`、`.listdir` |
| 进程 | `import os/subprocess`、`.system`、`.popen`、`.fork`、`spawn*` |
| 网络裸用 | `import socket`、`.connect`、`.bind` |
| 动态执行 | `exec` `eval` `compile` `__import__` `getattr/setattr` |
| 逃逸向量 | 任何 `__dunder__` 属性/名称（`__class__` `__globals__` `__builtins__` …） |

> `if __name__ == "__main__"` 是允许的（`__name__` 在良性 dunder 白名单里）。

### 返回

```json
{ "ok": true, "exit_code": 0, "duration_ms": 812,
  "stdout": "{\n  \"n\": 5\n}\n", "stderr": "",
  "stdout_truncated": false, "stderr_truncated": false }
```

失败时：`ok=false` + `error`（如 `ZeroDivisionError: division by zero`），超时为 `timed_out=true`。
**策略拒绝**（不是运行时错误）会作为工具错误返回，例如：

```
script rejected by the network-only sandbox: line 1: import of 'subprocess' is not allowed; permitted modules: …
Allowed imports: json, re, …. Filesystem, subprocess, socket and dynamic-execution APIs are never available.
Available helpers: fetch(url, …), fetch_json(url, …), html_to_text(html), …
```

### 示例

```python
import json, re
page = fetch("https://example.com/report", max_bytes=200000)
years = re.findall(r"(20[0-9]{2})", page["text"])
counts = {y: years.count(y) for y in sorted(set(years))}
emit({"status": page["status"], "years": counts})
```

## 4. `create_html`

**用途**：产出单文件离线可视化报告——结论（一行导语 + 模型写的摘要 + **原话**：收尾答复逐字全文，运行结束时自动注入，占位符会被真实答复替换）+ 逐条核对（一条一行：说法 / 核查结果 / 把握 / 来源编号，证据渐进披露，另有状态图例）+ 资料来源（可信度排序 + 「哪些说法用了它」反查）+ 时间线 + 关系图 + 查证过程（每次工具调用的记录 / 真正打开过的网址 / 被安全策略挡下的请求 / 模型留下的备注）。

### 参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | ✅ | — | 报告 id，会 slug 化（中文保留），重名自动加 `-2` |
| `title` | string | ✅ | — | 标题 |
| `query` | string | — | — | 原始研究问题 |
| `summary` | string | — | — | 摘要，支持段落、`- `列表、`**粗体**`、行内代码 |
| `items[]` | object[] | — | — | 主张：`claim` `detail` `status` `confidence` `source_ids[]` `tags[]` `date` |
| `sources[]` | object[] | — | — | 来源：`id` `title` `url` `kind` `reliability` `published` `quote` `engine` |
| `events[]` | object[] | — | — | 事件：`id` `label` `date` `description` `kind` `source_ids[]` |
| `relations[]` | object[] | — | — | 关系：`from` `to` `kind`(`causes/supports/contradicts/follows/related/mentions`) `note` `strength`(1–5) |
| `notes[]` | string[] | — | — | 局限、待查问题、方法说明 |
| `theme` | enum | — | 配置 | `dark` / `light` |

- `status` 允许：`verified` `supported` `unverified` `disputed` `refuted`（也接受 `confirmed/likely/contested/false` 等同义词）。
- `kind` 允许：`primary` `secondary` `academic` `official` `social` `unknown`。
- `source_ids` 可直接写 id、URL 或 1 起的序号，系统会自动解析；解析不到的会标成「未知来源」。

### 返回

```json
{
  "ok": true,
  "name": "rust-kernel-adoption-2026",
  "html_path": "/Users/mac/VeriScout/visualizations/rust-kernel-adoption-2026.html",
  "model_path": "/Users/mac/VeriScout/visualizations/rust-kernel-adoption-2026.json",
  "bytes": 48213,
  "stats": { "sources": 9, "items": 5, "events": 4, "relations": 5,
             "avg_reliability": 81.3, "verified_ratio": 0.6 },
  "warnings": ["no sources were attached: a report without sources is an unverified draft"]
}
```

### 规则

- 只接受 http(s) 来源链接，`javascript:` 之类会被丢弃并在 `warnings` 里说明。
- 不覆盖同名报告，而是新建 `name-2`。
- 所有文本在渲染时转义，无法注入脚本。
- **参数容错**：数字可以用字符串或百分比表示（`"88%"` → 88），列表可以只给单个值（`"s1"` → `["s1"]`），
  `items` 也可以是对象映射（`{"1": {...}}`）。纠正不了的元素会被**逐条跳过并在 `warnings` 中带下标报告**
  （如 `items[2] was skipped: empty claim`），不会整批丢弃。
- **调用后请核对返回值**：`stats` 的数量应与你的主张/来源数一致，`warnings` 非空时用 `edit_html` 补齐。

## 5. `edit_html`

**用途**：修改已有报告。改的是 JSON 模型，然后整体重渲染，因此 HTML 与数据不会不一致。

### 参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string ✅ | 目标报告 id |
| `set_title` / `set_summary` / `set_conclusion` / `set_theme` | string | 覆盖字段（`set_conclusion` 即报告 §1「结论」正文，通常由运行结束时的 `finalize` 自动写入） |
| `add_items[]` / `add_sources[]` / `add_events[]` / `add_relations[]` / `add_notes[]` | array | 追加 |
| `update_items[]` / `update_sources[]` | array | 按 `id`（或 URL）匹配后合并字段 |
| `remove_item_ids[]` / `remove_source_ids[]` / `remove_event_ids[]` | string[] | 删除（删来源会同时从主张里摘掉引用） |
| `remove_relations[]` | object[] | `{"from":..,"to":..}`，留空一侧表示通配 |

### 返回

```json
{ "ok": true, "name": "demo", "changes": ["title", "add_sources(1)", "add_items(1)"],
  "stats": { "sources": 3, "items": 4 }, "warnings": [] }
```

未提供任何操作时返回 `ok=false` 并说明「no edit operations were supplied」。

## 6. `delete_html`

**用途**：删除报告（HTML + JSON 模型）。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | ✅ | 报告 id；`"*"` 表示删除全部 |
| `confirm_all` | boolean | 删全部时必填 | 必须为 `true` 才允许清空 |

返回 `{"ok":true,"deleted":["x.html","x.json"],"count":2}`。
名称不存在时返回错误并**列出当前所有报告名**，便于模型改口。

安全：名称先 slug 化，路径再做「必须在 `visualizations/` 之内」的规范化校验，因此 `../../etc/passwd` 无法越界。

## 7. 工具选择速查

| 想做的事 | 用哪个 |
| --- | --- |
| 不知道从哪找起 | `web_search`（`scope=web`） |
| 要最新进展 | `web_search scope=news` |
| 要论文/权威研究 | `web_search scope=academic` |
| 已有一个 URL，要读原文 | `curl_tool` |
| 需要 API 返回的 JSON | `curl_tool`（JSON 会自动美化）或 `scripts_tool` + `fetch_json` |
| 一堆页面要抽字段/去重/统计 | `scripts_tool` |
| 要交付结论 | `create_html` → `edit_html` 补漏 |
| 报告过时了 | `delete_html` 重建，或 `edit_html` 增量修 |

## 8. 通过 MCP 被其他 agent 调用

`ves mcp` 启动标准 MCP（Model Context Protocol）stdio 服务，把本项目作为工具暴露给其他 agent（Claude Desktop / Cursor / agent 框架均可挂载）。

- **协议**：stdout 上每行一条 JSON-RPC 2.0 消息（MCP stdio 传输），日志走 stderr；不引入任何新依赖。
- **`tools/list` 返回 7 个工具**：上面的 6 个原样暴露（schema 完全一致）+ 1 个高层入口 `research`。
- **`tools/call` 行为与 `ves call` 完全相同**：同一个 `dispatch`、同一套协议 / 黑名单 / 私网 / 体积闸门；失败以 `isError=true` 返回，不会打断服务。
- **`research` 参数**：`query`（必填）、`max_steps`（可选）。它驱动本项目自己的模型循环跑完整研究，返回 `answer`、`reports[]`、`steps`、`tool_calls`、`usage`、`stopped_reason`；需要已配置模型 / API Key，耗时通常数十秒到数分钟。
- `initialize` 会回显客户端请求的协议版本；支持 `ping`；通知类消息（`notifications/initialized` 等）不产生响应。
